- (decision) CAP-1: a developer can consume a single token-driven CSS source of truth for every color, typography, spacing, shape, and elevation decision and a light/dark theme that persists per user across sessions; intent=eliminate one-off hex/font/spacing values and ship a coherent visual identity from day one; success=importing public/assets/css/tickettrade.css exposes var(--token) custom properties for the full palette (brand, semantic, status roles, rank tiers, surface, decorative) and typography/spacing/radii scales; raw hex values and hard-coded font-sizes outside the token file fail CI; data-theme persists to localStorage as tickettrade.theme with role-default fallback (dark for students, light for admin) and respects prefers-color-scheme on first visit; no flash of wrong theme on first paint
- (decision) CAP-2: a developer can compose every screen from a documented library of brand-aligned components (buttons, inputs, modals, bottom nav, rank/status badges, ticket-code block, listing card, leaderboard row, filter tabs, search input, bulk-action bar, analytics card, report/audit rows, tier progress, KPI counter, tier-privilege tooltip, star rating input, dispute/report/purchase/re-auth modals, toast, verified/velocity/on-break/avatar picker); intent=lock the visual and behavioral identity in reusable primitives so every later epic ships consistent UI without drift; success=every story 1.3, 1.4, 1.6 identity badges, 1.7, 1.8, 1.9 component renders to its documented anatomy with the accessibility attributes (role, aria-*, autocomplete, focus trap) declared in DESIGN.md and EXPERIENCE.md, and a developer reading the component recipe sees only var(--token) references
- (decision) CAP-3: a visitor (student or guest) can browse the marketplace as a corkboard with paper-flyer listing cards and a list-view toggle, with the cork degrading automatically on small screens and for reduced-motion users; intent=make the campus-corkboard metaphor the distinctive visual identity while keeping order/ranking information orthogonal to the decoration; success=cork texture background + paper card surfaces with deterministic ±2° rotation seeded by listing id + pushpin graphics render on ≥768px with cork/pin/rotation marked aria-hidden; a header toggle flips to a plain grid via aria-pressed and persists per session; on <768px and on prefers-reduced-motion the cork auto-degrades with identical listing order; the cork texture asset is ≤100KB and all motion is transform/opacity-only
- (decision) CAP-4: an assistive-technology or keyboard-only user can complete every primary task on every surface Epic 1 ships; intent=guarantee no user is excluded by a UI choice and the accessibility floor is verified at every commit; success=every color pair in the Contrast Ledger passes WCAG 2.1 AA (text ≥4.5:1, UI elements ≥3:1, large text ≥3:1); every interactive element is reachable by keyboard with visible focus outlines; modals trap focus and return it to the trigger; toasts and async status use role=status and role=alert live regions; all surfaces reflow to 320px without horizontal scroll (data tables may scroll inside their container); prefers-reduced-motion disables hover-lift, rank-S glow, modal slide-up, toast slide-in, save spinner, auto-save pulse; tap targets ≥44pt iOS / 48dp Android; redemption code input is autocomplete=off; numeric inputs use inputmode
- (decision) CAP-5: a developer or end user can use the Board, My Tickets, and Admin Dashboard surfaces exactly as the promoted mockups depict, and conflicts between any prior-run mockup and the current one resolve in favor of the current; intent=lock a canonical visual contract at the start so every later epic (especially 2-5) builds against a known reference instead of a moving target; success=mockups/board-mobile.html, mockups/my-tickets.html, and mockups/admin-dashboard.html ship as the canonical visual references, with their information architecture consistent with EXPERIENCE.md's route table, state patterns, and component patterns
- (decision) CAP-6: a developer or end user sees microcopy that follows the voice-and-tone rules (no emoji in functional UI, no streak language, no encouragement filler, no algorithmic reputation scores in user-facing chrome) and a CI linter blocks regressions of the locked anti-patterns; intent=keep the chrome honest and the copy consistent; success=composer test:banned greps the codebase for the documented anti-patterns (emoji in functional copy, streak counters, daily-login-bonus displays, badge counts on bottom nav, push notification strings, infinite scroll markers, nested modal markers, algorithmic-reputation-score markers, encouragement filler phrases like 'You're doing great!' / 🎉) and fails any PR introducing them without an explicit override; tier names appear with tier codes on first reference (Recruit (E), Rookie (D), Operative (C), Specialist (B), Elite (A), Legend (S)); dispute counts use 'N disputes on record'; purchase confirmations always include 'a reservation, not payment'
- (decision) CAP-7: an end user on a surface with no data or a failed fetch sees a clear, actionable empty or error state with a recovery action; intent=never leave a user confused by a blank surface and never mislead about the simulation-only nature of the transaction; success=documented empty/error copy for Board (no listings, no category results, no search matches, fetch fail), My Tickets (no tickets), Listing Modal (sold out, self-owned, wrong redemption code attempts 1-4/5/hr rate-limit, already-redeemed code, unauthorized redemption attempt) ships with a CTA / Clear filter / Clear search / retry action and never uses emoji or encouragement filler
- (decision) constraint: tokenized CSS — no raw hex, font-size, or spacing value may appear outside public/assets/css/tickettrade.css or DESIGN.md; adding a new visual value requires a named token first (bends every later screen's visual choices)
- (decision) constraint: theme bootstrap must not call Support\Auth::current_user() or Support\Time::now() — the localStorage read and data-theme flip happen before the framework boots, so first paint is the right theme with no FOUC (bends the order of front-controller work)
- (decision) constraint: design wins on conflict — DESIGN.md and EXPERIENCE.md are authoritative over any mockup, wireframe, or imports/* reference; promotion order goes spine → mockup → imports (bends what counts as a 'visual regression' in code review)

- (decision) constraint: reduced-motion is non-negotiable — hover-lift, rank-S glow, modal slide-up, toast slide-in, save spinner, and auto-save pulse are disabled under prefers-reduced-motion; state transitions still occur but without transform (bends which animations may live in the codebase at all)
